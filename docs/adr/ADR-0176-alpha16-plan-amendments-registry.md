# ADR-0176: Registry of the Alpha16–18 dated plan amendments

- Status: ACCEPTED
- Date: 2026-11-14
- Owner authorization: 2026-11-14 session ruling — all recommendations accepted, with
  four binding constraints (no alias in the production path, single source of truth,
  no JSR/Deno, full compliance with `docs/architecture/design-principles.md` P1–P8).
- Related: ADR-0173, ADR-0174, ADR-0175, ADR-0137, ADR-0177

## Context

Two owner-approved dated amendments were added to
`docs/architecture/alpha16-18-execution-plan.md` — §13 (2026-11-13, PR #1783,
squash `b194bb105`) and §14 (2026-11-14, PR #1787, squash `089ace0a8`, the same
change set that landed M09-2a/2b platform metadata). Both are decisions: §13:361
says "the amended readings below are authoritative", §14:462 says §14
"supersedes the §13.3 exception definition and the three §13.3 exception rows".

Neither amendment entered the decision registry. `docs/architecture/README.md`:93-95
says "Decisions live in the ADR index", `docs/adr/README.md`:9-11 makes this index
the registry, and `tools/repo/check-adr-index.ts`:41-44,334-360 reads only
`docs/adr/`, `docs/legacy/adr/` and `docs/adr/README.md` — it cannot see an
amendment inside the plan. `tools/repo/docs-index.ts`:292-306 only scans
`docs/architecture/` and `docs/agent-contract.md`, so there is no cross-carrier
topic check either. Risk R14 in the execution plan (`:283`) has
`Blocking gate = —` and `Owner decision? = No`, and its Detection is
"index/doc checks; review": the absence is a gap in the governance design, not a
missed gate run.

`docs/architecture/README.md` is generated by `docs-index:write` (`:91-92`), so it
cannot carry decision text by hand.

## Decision

**This record registers the two amendments; it does not restate them.** The
authority for their content remains
`docs/architecture/alpha16-18-execution-plan.md` §13 and §14 at their recorded
squash SHAs. This record holds only decision metadata:

| Amendment | Recorded | Authority | Subject |
| --- | --- | --- | --- |
| §13 (2026-11-13, owner-approved) | PR #1783 `b194bb105` | execution-plan §13:358-459 | M10-final / M11 start gate; five `16b-*` obligation slices; scope-exception definition |
| §14 (2026-11-14, owner-approved correction of §13.3) | PR #1787 `089ace0a8` | execution-plan §14:460-534 | corrected exception definition; three retained Alpha16 obligations |

`ADR-0175` remains the single current view (`:35-53`, D-3: "the authority is the
record, the view is generated"; "a second active statement of a topic is a gate
failure"). This record does not call itself a current view and does not copy the
plan's text, obligation tables, sign-off SHAs or ledger rows into the ADR registry.
That restraint is the P6 reason this record is additive rather than a second
source of truth (`design-principles.md`:174-180).

### Named deviations: §7 rule 1 (comply-or-explain)

`docs/architecture/alpha16-18-progress.md`:454-456 requires the slice PR that
changes a milestone to update its row in the same change and says "Do not batch
status updates into a later docs PR". Six merged M09 slice PRs did not carry that
row: #1782 `3d4992859`, #1785 `d0ea3824b`, #1787 `089ace0a8`, #1788 `7581fbf60`,
#1789 `f69dde8bf`, #1790 `fa6e5232d`. The deviation is named here, with the
principles it trades against: **P6** (one writer for one status fact) and **P8**
(a seam has exactly one named owner). It is registered by the owner ruling above
and is not waived: the correction is recorded as later readings in
`alpha16-18-progress.md` §4.7, in the amend-never-rewrite form of §4.2/§4.3,
without editing §3 rows or batch-rewriting history. `design-principles.md`:16-19
makes an unnamed deviation a defect to be reverted; this section is the naming.

No other deviation is registered here. In particular, the three retained
capabilities of §14.2 are **not** waived and no governance exception is granted
for them (§14.1, §14.3).

### Review gate (P7, `.github/PULL_REQUEST_TEMPLATE.md`:10-17)

1. **Platform?** Yes — the platform here is the repository's own standard
   artifacts: the ADR index and `check-adr-index.ts`, not a new registry.
2. **Compile-time cost?** Yes — one index row and one machine-checked record;
   no runtime surface, no product code, no public export.
3. **Runtime shape / server contract?** Not applicable; nothing ships to a
   browser or server.
4. **Nearest mature precedent and the deliberate difference?** ADR-0175 D-3
   (single current view, generated view, no hand-written truth) and ADR-0174's
   `Correction` (`:162-170`, add a later reading, keep the original text). The
   difference is deliberate: this record adds a *new decision record* rather than
   amending an existing ADR, because §13/§14 change M10/M11 dependency and
   §13.3 exception policy, which are not the decisions of ADR-0173/0174/0175.

## Consequences

- `docs/adr/README.md` gains exactly two entries (rule 1, listed exactly once);
  `adr-index:check` in `gate:source` covers them.
- `docs/architecture/README.md` is not hand-edited; if the active-document set
  changes, it is regenerated with `docs-index:write` and checked by
  `docs-index:check`.
- The `AMENDED` annotation is optional (`docs/adr/README.md`:17-18). The eight
  records with a dated amendment section but no annotation remain a **registry
  disclosure observation**, not a gate failure; whether to add the annotation is
  left as a separate, optional change.
- `docs/adr/README.md`:46's stale annotation text ("alpha.15 support remains
  (2026-11-03)") is corrected as a pure fact, without editing ADR-0152's body —
  the first-party Lit renderer retirement was executed 2026-11-08
  (`alpha16-18-progress.md`:441, C-01).
- Cross-carrier mechanical validation (a plan `## §N Dated amendment` section
  carrying a pointer to its ADR entry) is a **parallel, preventive** direction,
  not a prerequisite of this registration. Changing R14's `Blocking gate` from
  `—` is a gate-policy change with no existing authorization and remains an
  **owner-ruled candidate**, not an action taken here.

## What this record does not do

- It creates no milestone evidence, no P5 evidence, no gate record and no
  exit/sign-off (§13:362, §14:464, §13.5:445-451 stay in force).
- It creates no version, tag, publication, public API freeze or release claim
  (§14.4:534). `docs/release/release-state.json`:3-5 stays at
  `1.0.0-alpha.15` / `nextPlannedTrain: "not scheduled"`.
- It does not rewrite §1, §2, §12a, §13 or §14 of the execution plan, and does
  not modify any `packages/*` source or export map.
- It is not a release-path dependency edge. It restores the authority of later
  verdicts; it does not satisfy §13.5 P5, the five §12a proofs, M13 or the
  publication authorization in `CONTRIBUTING.md`:197.
