# Security baseline matrix

Date: 2026-11-13 (corrected 2026-11-14; see §4). Status: **index, not a claim.** This document records which
security controls this repository owns, where each is implemented, which channel
it reaches, and what remains a gap. It is not a compliance statement, not a
certification, and not a gate.

Why an index rather than an "OWASP mode": a framework-level switch that claims to
enable security is a second policy source (design principles P6/P8) and creates
the impression that compliance was reached. The controls below exist because
specific defects and audits forced them into the implementation; the matrix makes
them findable and keeps the gaps visible.

## 0. 通道划分（这是 A9 之后必须显式写清的）

| 通道 | 走什么 | 说明 |
| --- | --- | --- |
| request-time | `dispatchRequest` → 生成 handler → 内建 middleware 链（requestId/logger/cors/securityHeaders/csp） | 动态路由、POST、非静态回退；dev server / `oe start` / Nitro / Workers 同一条路径（parity 契约测试锁住） |
| static (SSG) | `static-serve.ts` 的 `tryStaticOutcome` 直接返回；**不经** middleware 链 | 静态文件响应只写 `content-type` + `cache-control`（`static-serve.ts:260-262`；纯静态 405 另带 `Allow`，`:384-388`）；**只有配置 `middleware.csp.policy` 时**才另经 policy-only `<meta http-equiv="Content-Security-Policy">` 交付（`postprocess.ts:75-139`、`ssg-render.ts:470-478`），meta 承载能力受限（见 §1 CSP 行与 §4） |
| static (host) | CDN / 反代 / Workers 宿主 | 框架不拥有；矩阵里标 infrastructure |

**结论性事实（2026-11-14 更正，取代 A9 的“预渲染页已覆盖”措辞）**：CSP 是**按应用配置**的通道能力——只有声明 `middleware.csp` 时才存在（request-time 走 header；SSG 仅在配置 `middleware.csp.policy` 时走 policy-only `<meta>`）。未配置时两条通道都不输出 CSP，由部署层/宿主自行决定。meta 通道不是 header 的等价物：`report-only` 与 `frame-ancestors` / `report-uri` / `report-to` / `sandbox` 在构建期 fail-closed（`OE_SSG_CSP_META_UNSUPPORTED`），per-request nonce 不适用于静态字节（警告后回退 policy-only）；这些形状需要请求时路由或宿主响应头交付。`X-Content-Type-Options` / `Referrer-Policy` / `X-Frame-Options` 等 11 个头**只在 request-time 通道**由框架设置，static 通道缺失 —— 这仍决定下表 owner 的划分。

## 2. 最小门禁（O11 待批；若批，则这样断言）

只断言四件事，秒级脚本，挂在既有 lane，不新增 CI stage：

1. 每个 `owner=framework` 行都有 Git-tracked 的测试路径且文件存在；
2. 每行都点名 channel（request-time / static / both）；
3. 已知残窗必须有 gap 文本且不可为空（含 `OPEN_ELEMENT_DISABLE_CSRF=1`、static 通道头缺失）；
4. 禁止出现 `compliant` / `certified` / `meets OWASP` 等合规语言；`owner=application|infrastructure` 的行必须在指南里有对应段落。

## 3. 明确不做

- `owasp: true` 之类的框架开关；把 auth/限流/WAF 塞进核心；把矩阵变成合规声明；用矩阵替代实现里的 fail-closed 检查。

## 4. 日期化更正（2026-11-14）

CSP 措辞按源码更正；矩阵仍是带缺口记录的索引，不是合规声明，本次不新增能力、不改策略。

- **CSP 是显式配置项，不是默认覆盖。** request-time middleware 只在应用声明 `middleware.csp` 时生成（`entry-descriptor.ts:370` 的 `if (mw?.csp)`）；SSG meta 还要求配置 `middleware.csp.policy`（`ssg-render.ts:470-478`）。未配置时框架不输出 CSP；需要时由宿主/部署层头或请求时路由提供（infrastructure 通道不变）。
- **request-time header 通道能力完整。** `entry-server-codegen.ts:87-131` 按配置输出 `Content-Security-Policy` 或 `Content-Security-Policy-Report-Only`，`nonce` 走逐请求 auto-nonce；meta 的限制不适用于该通道。
- **static meta 通道只承载 policy-only 策略。** `postprocess.ts` 对 `reportOnly` 与携带 `frame-ancestors` / `report-uri` / `report-to` / `sandbox` 的策略抛 `OE_SSG_CSP_META_UNSUPPORTED`（构建期拒绝，不降级）；`nonce: true` 记录警告并回退为 policy-only meta。需要这些形状时用请求时路由或宿主响应头。
- **静态文件响应头已按源码核对。** `static-serve.ts:260-262` 只写 `content-type`（和配置时的 `cache-control`）；11 个安全响应头与 CSP header 都只在 request-time 通道。纯静态部署的 GET/HEAD 之外方法由 `static-serve.ts:384-388` 返回带 `Allow` 的 405。
