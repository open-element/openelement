# Security baseline matrix

Date: 2026-11-13. Status: **index, not a claim.** This document records which
security controls this repository owns, where each is implemented, which channel
it reaches, and what remains a gap. It is not a compliance statement, not a
certification, and not a gate.

Why an index rather than an "OWASP mode": a framework-level switch that claims to
enable security is a second policy source (design principles P6/P8) and creates
the impression that compliance was reached. The controls below exist because
specific defects and audits forced them into the implementation; the matrix makes
them findable and keeps the gaps visible.

## 0. 通道划分（这是 A9 之后必须显式写清的）

| 通道 | 走什么 | 说明 |
| --- | --- | --- |
| request-time | `dispatchRequest` → 生成 handler → 内建 middleware 链（requestId/logger/cors/securityHeaders/csp） | 动态路由、POST、非静态回退；dev server / `oe start` / Nitro / Workers 同一条路径（parity 契约测试锁住） |
| static (SSG) | `static-serve.ts` 的 `tryStaticOutcome` 直接返回；**不经** middleware 链 | 只有 `content-type` + `cache-control`；**CSP 另经 `<meta http-equiv>` 交付**（`postprocess.ts:80-116`） |
| static (host) | CDN / 反代 / Workers 宿主 | 框架不拥有；矩阵里标 infrastructure |

**结论性事实（A9 更正）**：CSP 对预渲染页**已覆盖**（meta 通道）；`X-Content-Type-Options` / `Referrer-Policy` / `X-Frame-Options` 等**只在 request-time 通道**由框架设置，static 通道缺失 —— 这决定下表 owner 的划分。

## 2. 最小门禁（O11 待批；若批，则这样断言）

只断言四件事，秒级脚本，挂在既有 lane，不新增 CI stage：

1. 每个 `owner=framework` 行都有 Git-tracked 的测试路径且文件存在；
2. 每行都点名 channel（request-time / static / both）；
3. 已知残窗必须有 gap 文本且不可为空（含 `OPEN_ELEMENT_DISABLE_CSRF=1`、static 通道头缺失）；
4. 禁止出现 `compliant` / `certified` / `meets OWASP` 等合规语言；`owner=application|infrastructure` 的行必须在指南里有对应段落。

## 3. 明确不做

- `owasp: true` 之类的框架开关；把 auth/限流/WAF 塞进核心；把矩阵变成合规声明；用矩阵替代实现里的 fail-closed 检查。
