## What the shell is

`createGeneratedElementClass(descriptor)` builds a class that directly extends
`HTMLElement`; `defineGeneratedElement(descriptor)` performs the explicit
`customElements.define`. The descriptor is a compiler-private contract:
`tag`, declared properties (`name`, optional `attribute`, `type` limited to
`string` / `number` / `boolean`, `reflect`, `default`), the generated
`create<Name>Recipe` factory, and an optional `createBindings()` factory. It is
not author syntax; `defineGeneratedElement` is a test/emitter hook, not the
M09-1 registration decision.

The shell owns only the platform edge:

- it selects mount (`insertRecipe`) when no generated region or server DOM
  exists, and claim (`claimRecipe`) when retained/server DOM exists; it never
  re-derives mount, claim or SSR lowering;
- it reads and validates the descriptor before any `customElements.define` or
  DOM write, using the repository's coded error dialect;
- it exposes the generated props record with per-read getters and one
  shell-owned `propsChanged` signal;
- it converts through the one canonical leaf instead of copying a conversion
  table; `facade-host.ts` continues to export `convertFromAttribute` and
  `convertToAttribute` for existing compiled-runtime callers, with identity
  pinned by a test;
- it does not import `facade-host.ts`, `runtime-program.ts`, the compiled
  kernel, the runtime barrel or the Part Program executor.

## Module graph: the old backend is not reachable

The module-graph test performs a real Vite build of the generated module, the
recipe/runtime primitives and the shell, and records two module-ID sets:

1. the emitted chunk's `moduleIds` (what the bundle actually keeps), and
2. the plugin's `moduleParsed` IDs (the pre-tree-shake parsed graph).

Both sets must contain `shell.ts` and `property-conversion.ts`, and both must
exclude the forbidden old-backend suffixes: `facade-host.ts`,
`runtime-program.ts`, `runtime.ts`, `runtime/kernel.ts`,
`runtime/program-kernel.ts`, `runtime/parts.ts`, `runtime/hydrate.ts`,
`runtime/fresh-dom.ts`, `runtime/props.ts`, `runtime/blocks.ts`,
`runtime/revive.ts`, `runtime/error-boundary.ts`,
`runtime/pre-upgrade-events.ts`, `runtime/hydrate-recovery.ts`,
`runtime/blocks-seam.ts` and `runtime/hydrate-seam.ts`. The neutral generated
leaf primitives (`recipe.ts`, `values.ts`, `bindings.ts`, `markers.ts`,
`claim-invariants.ts`, `lineage.ts`, `observability.ts`,
`static-sibling-ranges.ts`) are allowed because they are shared runtime
primitives, not the Part Program executor.

The parsed graph matters: a re-export-only import of `facade-host.ts` is
tree-shaken out of the emitted chunk but still appears in `moduleParsed`, so
the emitted-only assertion would miss precisely the original blocker edge. A
negative control during review re-added that re-export and observed the parsed
assertion fail while the emitted assertion stayed green.

Boundary: the deny list is hand-maintained and the evidence covers this test
entry only. It is not a proof over the future production entry or a packed
consumer; that belongs to M09-1/M10. The protocol `part-program.ts` wire grammar
is not an executor and is not part of the deny list.

## The four conformance blockers and fixes

The independent review of the first implementation raised four blockers. The
landed slice fixes them and pins each with a test:

- **F1 — teardown owned the host, not the region.** `dispose(true)` previously
  removed every `childNodes`. The shell now records the top-level nodes of the
  last successful mount/claim on the element state and removes exactly that
  range. Host-appended nodes, borrowed server DOM from a failed claim, and DOM
  that was never mounted stay. `dispose(false)` releases the ownership record,
  so a later `dispose(true)` cannot upgrade it; a failed claim leaves the
  borrowed DOM intact.
- **F2 — the constructor inspected attributes.** It no longer reads attributes
  or children. Platform observed-attribute replay runs
  `attributeChangedCallback` before `connectedCallback`, so state is seeded
  before the recipe is created. The parser-created upgrade test patches
  `getAttribute` and observes zero constructor reads.
- **F3 — pre-upgrade own data properties shadowed the accessor.** On the first
  connect, before `createRecipe`, own data descriptors for declared properties
  are read, deleted and re-applied through the property contract. A real
  pre-upgrade JS set wins over the replayed attribute, a value restating the
  declared default is ignored, and a non-configurable own property fails loudly
  instead of staying silently shadowed.
- **F4 — attribute removal did not mirror the reflected default.** Removing a
  reflected attribute resets the property to its declared default and then
  re-serializes the current value to the attribute mirror under the reflection
  guard. This is independent of the value-equal short circuit, so string `''`,
  number `0` and boolean `true` defaults are restored.

Teardown error handling also preserves the original error: every cleanup is
attempted and the first failure is the one surfaced, rather than a later root
cleanup replacing the recipe/claim failure.

## Explicitly unsupported and boundary

This shell is a bounded M09-0 slice. It does **not** implement or claim:

- **Shadow DOM / DSD**, slots, `delegatesFocus`, styles or theme, root-mode
  selection, or any shadow-tree claim/directory work.
- **Event declarations**, event-part activation, or an authored event surface.
- **Forms**: `formAssociated`, `ElementInternals`, form reset/validation or
  form participation.
- **Context**: the Community Context Protocol (`context-request`,
  `provideContext`, `consumeContext`) is not wired into the generated element
  lifecycle.
- **Rich property reflection**: only `string` / `number` / `boolean`
  properties are admitted; array/object reflection and richer coercion remain
  outside the slice.
- **Author lifecycle hooks**: there is no author `onConnect` / `onDispose`,
  setup-once count, or focus/selection/scroll restoration across the
  disconnect window.
- **The full §4.1d reconnect-resource contract**: only the narrow retained-DOM
  + fresh root/projection owner + retained bindings/`propsChanged` path is
  proven. `createBindings()` is allocation-only because the shell has no
  element-lifetime cleanup owner; `propsChanged` is element-lifetime and is not
  disposed.
- **SSR classification**: empty server output is indistinguishable from "no
  server DOM", so the first connect mounts an empty region; only a reconnect
  claims.
- **Light-DOM projection**: existing children are treated as server/retained
  DOM, not as authored light children or slot content.
- **Production entry**: no class emitter, statics/ABI, plugin/compile wiring,
  registration decision or package export. The descriptor remains internal and
  is not an author API. M09-1, M09-2, M09-3 and M09-4 are not started by this
  record; M13 three-engine and packed-consumer evidence are also not claimed.
- The M08 dynamic-text residual (adjacent text slots coalesce into one Text
  node) is unchanged here; this slice's claim case deliberately uses one dynamic
  text slot per element.

`dispose(true)` while the element stays connected leaves it without a
projection until the next connect event; the shell does not auto-remount. That
is the explicit teardown contract, not a hidden recovery path.

## Publication boundary: alpha15

`@openelement/element` publishes `src/**`, while the generated-element shell is
intentionally unreachable from every packed entry until M09-1 wires the first
official consumer. The alpha15 package therefore carries one exclusion in its
`files` list:

```json
"files": ["src/**", "README.md", "LICENSE", "!src/internal/compiled/generated-element"]
```

The exclusion names the whole unpublished slice directory; it does not
enumerate files. It is a release boundary — the experimental slice must not
ship in the alpha15 artifact — not a gate exemption, a scanner allowlist, or a
runtime allowlist. Without it, `pack:dry-run` fails closed on a publish-scoped
source module that no packed entry reaches. No public export is added merely to
make the graph reachable.

**Removal condition:** the M09-1 change that wires the first official consumer
(the emitted constructor/registration point) MUST delete this exclusion and
prove packed consumption, not only source-level tests. That proof rebuilds the
tarballs and runs at least `pack:dry-run`, `pack-surface:check` and
`consumer:packaged-element` against them. Until then, the directory stays
outside the published package.

Alpha15 verification at this change: `pack:dry-run` and `pack-surface:check`
pass with the exclusion, and `docs-index:check` passes.
