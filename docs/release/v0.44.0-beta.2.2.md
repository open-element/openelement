# v0.44.0-beta.2.2

Beta.2.2 closes the dual-renderer Framework Mode checkpoint (#1321): Native and Lit applications now share one router, one resolved Document seam, one effective form-submission contract, and one packed-consumer qualification — proven end to end from frozen release tarballs, not workspace aliases.

## Highlights

- **Dual-renderer Framework Mode (#1339)** — paired Native and Lit reference applications covering the full product flow: list → detail → create/edit form → validation failure → success → error → redirect → both 404 channels, plus loader/action outcomes, response-header channels, SSG vs request-time data separation, the JS-disabled native POST matrix, back/forward navigation, and submitter name/value overrides. Renderer selection is explicit (`openElement({ renderer })`, `native` by default); an unsupported `appShell` + `lit` combination fails closed at build time. Lit reference server runtime: Node 24 with pinned `lit@3.3.3`, `@lit-labs/ssr@4.1.0`, `@lit-labs/ssr-client@1.1.8`.
- **Resolved Document seam (#1326)** — `resolvePageDocument` (`@openelement/app/document`) resolves page meaning exactly once per render, before either serializer runs: title, canonical, and hreflang alternates have a single owner, pure per request (no fetch, cache, or global request state), identical for Native and Lit, normal pages, error pages, 404s, and SSG/request-time combinations.
- **Public metadata convergence (#1327)** — the www site writes page meaning once at SSG time from route descriptor heads; sitemap and search consume only legal public inputs with fail-closed eligibility for unenumerated dynamic routes. The post-build SEO rewrite and the duplicated route SEO map are deleted — there is no second writable owner for title/canonical/hreflang.
- **WTR pilot (#1333 slice)** — official compiled-ESM Web Test Runner lane: 25 tests × Chromium/Firefox/WebKit covering forms/FACE, validation/reset/submitter/IDL overrides, composed events, lifecycle, and dialog/dropdown overlay contracts, with a five-proof negative exit contract (failing assertion, missing browser, broken transform, zero-tests, no-matching-files each proven to exit 1). facade-dom residual migration stays with Beta.2.3.
- **Bounded experiments (#1156)** — Oxc (7/7 sample parity incl. source-map position verification), TS7 (hard 20/20 against the exact stable `typescript@7.0.2`, CLI-scoped — no Compiler API compatibility is claimed; the 20 catalogued consumer files stay on TS 5.9), and CEM (field parity with a ~90-line plugin PoC, PROCEED with conditions). Inputs, versions, commands, and results are bound to recorded SHAs; performance figures are bounded single-host microbenchmarks only. No production migration.
- **Packed-consumer qualification** — both renderers are installed from frozen `pack:dry-run` tarballs in a workspace-external temp dir and qualified over 20 cells: install, packed-declaration typecheck, **dev server**, build, `cli:start`, standalone `serve.mjs`, form 422 + 303 PRG over the wire, Chromium browser continuation, and browser-bundle + declaration-graph boundary. The dev cell drives the public `deno task dev`: live routes/forms/404s, component and route-module edits reach the served document with stale content gone, a deliberately broken edit answers 500 (never stale success) and recovers on revert, and stop/restart frees the port. 20/20 PASS on macOS and Linux CI.

## Defects fixed in this checkpoint

All seven were found by the new qualification lanes and carry fail-first regression evidence:

1. **Lit client bundles silently omitted the form-enhancement layer** — semantic analysis only recognized `data-open-enhance` as a JSX attribute, so Lit `html` templates never pulled the shared enhancement layer into the client bundle and "enhanced" Lit tests were passing on native browser submissions. Template-literal detection now applies the same attribute-shape rule as JSX, with real interception/morph proof in all three engines.
2. **Lit dev SSR rendered stale component classes forever** — the long-lived SSR registry captured the already-wrapped `define()` as its "original", so re-evaluation never overwrote the stale class. The wrapper now installs once, the true original define is retained on the registry (`SSR_REGISTRY_ORIGINAL_DEFINE`), only entry-owned tags may be re-registered through it, and external conflicts stay fail-closed.
3. **`open-dropdown` focus-return race** — focus capture/reset moved from the queued `toggle(open)` handler to synchronous `beforetoggle(open)`, covering menu-button composition and direct `showPopover()` paths; regression is RED against the pre-fix behavior and GREEN in Chromium, Firefox and WebKit, with Escape/light-dismiss/repeated-open/disconnect-reconnect assertions unchanged.
4. **Lit islands inserted by enhanced responses never hydrated** — lifting `defer-hydration` ran only at first module load, so islands inserted by a later enhanced form response stayed inert. The Lit enhance callback now lifts the marker for admitted, already-loaded tags on every morph before the scheduler rescans; tags whose scheduling condition has not fired stay deferred.
5. **Stale form responses could overwrite a newer page** — a late success or failure from a form whose page had exited could still touch the DOM, rewrite the URL, or trigger the reload fallback. Both paths now check per-form sequence, connection, document identity, and the fragment-insensitive page URL before any side effect; fragment-only changes keep the result and concurrent independent forms keep per-form sequencing.
6. **`<base target>` was ignored by the enhancement layer** — an absent form target now inherits the document's first `base[target]` per HTML's get-an-element's-target algorithm (submitter `formtarget` still wins; an explicitly empty target stays empty), so `<base target="_blank">` keeps the browser's native new-tab behavior instead of being intercepted.
7. **Dev server could wedge at 500 after reverting a broken edit** — Chokidar's `fs.watch` backend can drop a change event inside its 50ms window, leaving Vite's SSR error cached forever (hit by the packed Lit consumer on Linux). Unless the user configured the watcher, the adapter now sets `awaitWriteFinish` (50ms stability, 10ms poll) so the settled final write is delivered; explicit watcher settings always win. The packed consumer forces the `fs.watch` backend on every host so this path is exercised everywhere.

Also in this line: effective submission tuple correctness (submitter overrides win; GET/DIALOG/text-plain/cross-origin/non-default-target fall back before `preventDefault`); urlencoded bodies are byte-identical to native on the wire including the platform CRLF newline rule, proven in all three engines; three CodeQL findings fixed without dismissing alerts or excluding paths.
