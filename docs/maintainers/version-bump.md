# Version bump (the stamp knob)

`tools/repo/version-bump.ts` is the single knob for cutting a release train.
One command stamps every version site in the tree; the dry run is the review
surface. This page replaces `version-bump-transitional.md`, deleted when the
alpha9 C5 rewrite (#1508) absorbed the last hand-edited sites. The historical
lessons that manual carried are folded in below.

## The ten text points

| # | site | token |
| --- | --- | --- |
| 1-4 | `packages/{element,router,create,ui}/package.json` | `version` |
| 5 | `packages/create/src/version.ts` | `CREATE_VERSION` |
| 6 | `docs/release/release-state.json` | `sourceVersion` (bare) + `activeTarget` (`v`-prefixed) |
| 7 | `tools/repo/check-release-state-machine.ts` | `ADMITTED_ACTIVE_TARGET` |
| 8 | `tools/repo/check-release-state-machine.test.ts` | its twin fixture (`sourceVersion`, `activeTarget`, workspace-versions map) |
| 9 | `README.md` | the source-tree sentence |
| 10 | `README.zh.md` | the 源码基线 sentence |

Plus the tracked generated outputs, refreshed by the same command through the
`generate:all` face after the text points are written:

- `packages/ui/src/generated-manifest.json` embeds the package version. It is
  a TRACKED generator output — the alpha.8 stamp (2026-10-04, PR #1515) missed
  it and failed `workspace-clean-after` in source-matrix/fresh-clone, because
  gate:source regenerates it mid-run. The knob now runs `generate:all`
  itself, so a stamp commit cannot forget it.
- `www/app/data/_generated-release-line.ts` mirrors
  `docs/release/release-state.json` (untracked, regenerated by the www
  content generator; the `www-release-anchor` audit cross-asserts it).

## Procedure

```sh
pnpm --dir tools/repo run version-bump 1.0.0-alpha.N              # dry run (default)
pnpm --dir tools/repo run version-bump 1.0.0-alpha.N --dry-run    # explicit dry run
pnpm --dir tools/repo run version-bump 1.0.0-alpha.N --write      # apply + generate:all
```

1. **Review the dry run.** It prints the diff of all ten points plus the
   generated-output preview, and fails closed if any anchor has drifted (for
   example a hand-edited sentence the rewriter can no longer find).
2. **Apply with `--write`.** The command writes the ten points, runs
   `generate:all`, and re-checks the whole surface (including the www anchor)
   before exiting. `pnpm install` afterwards normally produces NO lock diff:
   the workspace's single `pnpm-lock.yaml` records workspace links as
   `workspace:*` / `version: link:...`, which carry no version token. Run it
   once anyway and commit a diff if one appears.
3. **Write the CHANGELOG entry by hand.** Authored prose stays outside the
   knob.
4. **Verify.** `pnpm --dir tools/repo run version-bump <current-version>`
   (dry run against the just-written tree prints "tree already at …"; with no
   argument the script prints usage and exits 2), then the usual
   `vp run check` face.

## What deliberately does NOT move at bump time

- **release-state.json `registry` dist-tags and `latestPrerelease`** — they
  record what npm actually serves, which lags the source version until the
  packages publish. The offline state-machine check and the read-only
  registry check both assert this lag is represented truthfully.
- **`packages/create/README.md`'s pinned install example** — it documents the
  version npm's `@alpha` tag resolves to (registry truth, same lag).
- **The npm `latest` dist-tag** — never moves onto a prerelease.

## Guards that ride the knob

- The shipped-source historical-release-name scan (the retired
  0.23/0.40/0.42/0.44 lines must not reappear in what consumers import).
- `wwwReleaseAnchorDrift` — the www source-line anchor stays derived from
  release bookkeeping truth.
- Cross-checks after the fact: `@openelement/tools-release#graph:check`
  (every package manifest version and `CREATE_VERSION` against
  release-state.json `sourceVersion`) and
  `@openelement/tools-repo#release:state-machine:check` (the admitted-train
  model).

Advancing `ADMITTED_ACTIVE_TARGET` remains a reviewed change to the state
machine: a train enters through the stamp commit that carries the constant
move, never by quietly editing `release-state.json` alone. The knob exists so
the constant and its twin fixture move together, not so the admission is
quiet.
